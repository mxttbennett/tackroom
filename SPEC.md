# SPEC: extra instruction files in every root doc

Status: requested 2026-10-17. PR only; merge needs separate approval. Earlier specs are in git history (`git log -- SPEC.md`).

## Problem

Users keep always-on files beside `AGENTS.md` (a voice file such as `SOUL.md`, a user profile kept in a notes vault). Claude Code can `@`-import them from `AGENTS.md`, but no other harness expands imports, so today they reach Claude Code only, or get pasted into `AGENTS.md`.

## Behavior

- **`instructions:` in `tackroom.yaml`.** A list of file paths, relative to the config root or `~/`-rooted. Validation trims entries and rejects empty paths, duplicates and `AGENTS.md` itself. `tackroom.local.yaml` replaces the list when it sets one; `instructions: []` turns it off for one machine.
- **Composed root doc.** With a non-empty list, each harness's root doc carries `AGENTS.md` followed by the listed files, in order, behind a `<!-- Generated by tackroom from ...; do not edit directly. ... -->` header naming the sources.
  - Claude Code expands `@path` imports (https://code.claude.com/docs/en/memory#import-additional-files), so `~/.claude/CLAUDE.md` holds one import line per source and stays live when a source changes.
  - Every other harness gets the sources' text. `status` reports the copy as drifted ("stale generated file") when a source changes; `sync` rewrites it.
  - A listed file missing on this machine is skipped and named in `status`, text and JSON (`root_instructions.missing_sources`); the rest still sync.
- **States.** A composed root doc is synced when its bytes match. A plain link, an identical copy of `AGENTS.md`, or an older generated file is drifted and rewritten in place (the link is removed first, so the write never follows it into `AGENTS.md`). Any other file is a replaceable conflict, as before. Without a list, a generated file is drifted and goes back to a plain link.
- **New root docs.** Hermes: `~/.hermes/SOUL.md`, its only always-loaded file (Hermes has no global `AGENTS.md`; https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files). Hermes seeds a default there, so the first sync reports a conflict; setup does not import that file into a new `AGENTS.md`. OMP: `~/.omp/agent/AGENTS.md`, which OMP prefers over its `~/.agents/AGENTS.md` fallback (verified with canary files).
- **Docs.** `docs/setup.md` lists Pi, OMP and Hermes root docs and documents `instructions:`; README, the tackroom skill and the site demo show it.

## Not changed

- Without `instructions:`, every root doc is still a plain link to `AGENTS.md`.
- Root docs stay outside the five synced surfaces; this only changes what the existing root doc contains.

## Open

- Droid lists `~/.factory/`, `~/.agents/` and `~/.agent/` as personal instruction directories (https://docs.factory.ai/cli/configuration/agents-md). Whether it loads more than one of them was not measured (no Droid login on the test machine). If it does, Droid with the config root at `~/.agents` sees `AGENTS.md` twice, as it already does with today's link.

## Acceptance tests

- Copy lifecycle (Droid): a plain link is drifted, sync writes the composed file without touching `AGENTS.md`, status is then synced, editing a source makes it drifted, removing the list relinks.
- Claude Code gets import lines and stays synced after a source edit.
- A user-written file is a replaceable conflict.
- Hermes inspection wires the root doc; setup skips Hermes's seeded `SOUL.md`.
- Config validation and overlay merge.
- Sandboxed home run: `sync` writes composed docs for Claude Code, Codex, Droid, OMP and Hermes, `--replace-conflicts` backs up Hermes's seed, `instructions: []` in the local overlay reports every doc as drifted back to a link.
- `go test ./...` passes.
